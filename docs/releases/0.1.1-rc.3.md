# dsh-pet 0.1.1-rc.3 修复发布 / Repair release

[中文](#中文) | [English](#english)

<a id="中文"></a>
## 中文

`0.1.1-rc.3` 让 npm 用户安装 `@luv1211/dsh-pet-desktop` 后获得完整的运行时包和可启动的浏览器控制界面。该版本针对早期发布在安装阶段才暴露的问题建立了构建、打包和安装验证。

### 修复内容

- `@luv1211/dsh-command-pet` 现在在发布前构建，并在 tarball 中包含 `lib/index.js` 运行时入口；不再只发布类型声明。
- `@luv1211/dsh-pet` 不再声明无法在独立插件仓库生成的 `./typert` 远程通信入口。宠物服务提供同源 JSON API，浏览器界面通过该 API 读取快照和提交操作，因此不需要 `typert.host.js`。
- `publish-all.mjs` 在访问 npm 前执行 `release:verify`。该门禁依次执行类型检查、测试、构建、tarball 公开目标检查，以及只从生成 tarball 安装的 Cordis Loader 与 API 烟雾测试。
- `@luv1211/dsh-pet-desktop` bundle 固定了桌面伴侣、宠物服务、`/pet` 命令和浏览器 UI 的加载顺序；用户只需安装 bundle。

### 安装

```sh
npm install --global @deepseek-ai/dsh@0.1.1-rc.2
dsh plugin --profile web add @luv1211/dsh-pet-desktop@0.1.1-rc.3
dsh web
```

需要 Node.js `^22.19.0` 或 `>=24`。若系统提示找不到 `dsh`，重新打开终端后再试；此版本的用户安装路径不依赖 pnpm。已安装旧版 bundle 的用户重新运行第二条命令以将 profile 指向此版本。

### 已知限制

- 本版本面向 npm 已发布的 DeepSeek Harness `0.1.1-rc.2`。上游 `0.1.2-alpha.1` 的客户端内部模块表已经变化，不能作为此版本的兼容目标。
- 设置页导航中的“宠物”条目仍使用 Harness 对第三方设置区块的默认齿轮图标。让插件随包提供导航图标需要 Harness 为 `settings.section` 增加图标渲染接口；仅在 dsh-pet 内放入图标文件不会被当前设置壳加载。
- 宠物目录没有外部文件系统监听。目录在启动、导入、替换或用户在设置页点击刷新后更新。

## English

`0.1.1-rc.3` lets npm users install `@luv1211/dsh-pet-desktop` with complete runtime packages and a browser control surface that can start. This release adds build, pack, and installation checks for failures that earlier releases exposed only after installation.

### Fixed

- `@luv1211/dsh-command-pet` builds before publication and its tarball includes the `lib/index.js` runtime entry instead of type declarations alone.
- `@luv1211/dsh-pet` no longer declares the `./typert` remote entry that an independent plugin repository cannot generate. The pet service provides a same-origin JSON API for snapshots and actions, so the browser surface does not require `typert.host.js`.
- `publish-all.mjs` runs `release:verify` before contacting npm. The gate runs type checks, tests, builds, concrete tarball public-target checks, and a Cordis Loader plus API smoke test that installs generated tarballs only.
- The `@luv1211/dsh-pet-desktop` bundle fixes the loading order for the desktop companion, pet service, `/pet` command, and browser UI. Users install one bundle.

### Install

```sh
npm install --global @deepseek-ai/dsh@0.1.1-rc.2
dsh plugin --profile web add @luv1211/dsh-pet-desktop@0.1.1-rc.3
dsh web
```

Node.js `^22.19.0` or `>=24` is required. If the system cannot find `dsh`, reopen the terminal and retry; the end-user installation path does not require pnpm. Users with an older bundle can rerun the second command to point the profile at this version.

### Known limitations

- This release targets the npm-published DeepSeek Harness `0.1.1-rc.2`. Its `0.1.2-alpha.1` upstream line changed client-internal module tables and is not a compatible target.
- The Pet item in settings navigation keeps the default gear that Harness assigns to third-party settings sections. A plugin-owned navigation icon requires a `settings.section` icon-rendering API in Harness; adding an image file inside dsh-pet alone cannot make the current settings shell render it.
- The pet directory has no external file-system watcher. It refreshes at startup, after import or replacement, or when the user selects refresh in settings.
